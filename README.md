# 撷思 PickThought

**书是你的,想法是社区的——撷思把后者缝进前者。**

下载书不是我们想做的，我们只负责采摘想法。

撷思是一款非官方 KOReader 插件,只做一件事:从微信读书拉取一本书的**热门划线与公开想法**,引文对齐后注入到你本地已有的 EPUB。阅读时点按虚线文字,弹窗看这一段其他读者想了什么。

## 为什么有这个项目

读自己搞来的 EPUB,阅读体验唯独缺了一块:微信读书 App 里那些沉淀在每段文字上的读者想法。一本书的社区记忆,是阅读体验的另一半。

现有的微信读书 KOReader 插件都绕不开"下载书"——可你的书已经有了,而且往往是更好的版本。一旦让它下载,你的精校版就废了;它还要顺带做时长上报、进度同步、书架浏览,把一整套东西捆进来。我们要的只是"想法"这一块,而它的实现又必须依赖"书也是我下的"(否则划线位置对不上)。

撷思反过来:**书不动,想法搬过来**。难点在于你的本地版和微信版正文有差异,划线位置不能直接套——所以我们做了一套引文对齐的章节映射,把微信的划线"翻译"到你的版本上。

## 它做什么

- **拉热门划线与公开想法**:微信读书 web 端点,Cookie 鉴权,登录态自动续期。
- **引文对齐注入**:把每条划线的引文与本地 EPUB 正文做匹配,在对应位置注入虚线锚点。支持"微信一章 = 本地多章"的拆分注入、微信与本地章号体系不一致、精校版文字差异。
- **原地替换,进度保留**:同步完成后直接替换你正在读的书(KOReader 的阅读进度跟着文件路径走,不受影响),原版自动备份为 `原书名.epub.orig`,菜单一键还原
- **后台同步,不打断阅读**:同步跑在独立子进程,进度框可「转入后台」继续看书;防锁屏、断点续传、KOReader 重启后自动接管仍在跑的任务
- **大书防风控**:单次最多拉 300 个新章节,章间随机停顿;剩余章节手动补,或阅读接近已同步末尾时自动后台补
- **离线重注**:完整同步过一次后,零网络重跑映射+注入(换了本地书版本、还原后想重打时用)
- **点击秒开**:想法存 per-book SQLite(`thoughts.db`),点锚点单次索引查询,弹窗用 KOReader 原生 TextViewer 分页

## 它不做什么

- **不下载书**——书必须是你本地已有的 EPUB。下载书不是我们想做的，我们只负责采摘想法。
- **不上传任何数据**——对微信读书只读不写,不做时长上报、不做进度回传
- **不做书架浏览/搜索下载**——这些与"读自己已有的书"相悖
- **不丢原书**——`.orig` 备份兜底,「还原原书」随时退回
- **不做"按段落在线拉全量想法"**——见下方"天花板"说明

注入过的书内嵌 `pickthought.json` 标记:对它再次注入会被拒绝,同步永远从 `.orig` 干净源重做,不会叠加污染。

## 关键设计抉择

**原地替换,而不是生成副本。** 副本会让书架出现两本同样的书、阅读进度断层(你得在新副本上从头读)。原地替换保留进度,书架不膨胀,代价仅是多一个 `.orig` 备份文件——可一键还原,可接受。

**引文对齐,而不是照搬数字 range。** 微信返回的划线位置是它自己正文里的字符偏移,你的本地版文字一旦有差异(精校、排版、不同版本),偏移就全错。唯一可靠的路是用划线引文去本地正文里找对应位置。代价是有匹配失败率——引文被精校改得面目全非、或俗语在多章复现时会定位失败,这部分划线只能放弃。

**后台子进程,而不是前台阻塞。** 同步一本几百章的大书要几分钟,卡在阅读界面既看不了书又取消不了,是最差的体验。子进程跑、UI 放开,是必须的。代价是实现复杂(进程判活、看门狗、防锁屏、重启接管),但这套逻辑我们从原 miuread 继承并加固,久经真机考验。

**SQLite 存想法,而不是 JSON。** 早期用 per-chapter JSON,点锚点要全章加载+Lua 遍历找 range,剑来这种 643 章的书首点要 150-550ms。换 per-book SQLite 单次索引查询后降到 20-35ms。这块实现移植自 weread.koplugin。感谢付出

**原生 TextViewer 弹窗,而不是自绘 HTML。** 自绘能做更花哨的排版,但 474 行手搓 widget 维护重、真机翻车多次。原生分页弹窗稳定省心——能用原生的,就不自己造。

**AGPL-3.0 许可证。** 我们移植了 weread.koplugin 的 SQLite 模块(AGPL-3.0),按协议要求,本项目必须以相同协议开源。这也和我们"开源、可审计"的初衷一致。

## 一个诚实的天花板

拉到的想法数量取决于微信读书接口返回的内容——它每章只给一小撮热门评论。

你在手机 App 里点某句话看到成百上千条想法,那是另一个"本段想法聚合"接口,我们没用。

所以同一句话,撷思弹窗里的想法可能比 App 少。突破这个天花板需要探测并接入那个聚合接口,是未来工作。

## 环境要求

- **KOReader ≥ v2025.08**(硬性,不做旧版 fallback)。EPUB 的解包与重打包依赖该版本起内建的 `ffi/archiver`(libarchive 的 FFI 封装);SQLite 依赖内建的 `lua-ljsqlite3`。更早版本会提示缺少依赖而无法使用。
- 主要在 Kindle 上开发测试;其他 KOReader 平台(Kobo/Android 等)依赖均为 KOReader 内建,理论可用但未完整验证。

## 安装与使用

1. 下载后解压到 KOReader 插件目录(目录名必须保持 `pickthought.koplugin`):

   ```text
   koreader/plugins/pickthought.koplugin
   ```

2. 重启 KOReader,主菜单「工具」中找到「撷思」。

3. 使用流程:
   - 「账户」里扫码登录微信读书
   - 文件管理器菜单「选择书籍同步想法」直接选书绑定+同步,或打开一本书后在菜单里「绑定微信读书」→「同步划线与想法」
   - 同步完成后直接阅读,点虚线看想法;「选择书籍更多操作」里可离线重注 / 续拉 / 还原原书

## 代码结构

```text
pickthought.koplugin/
├── main.lua                  # 插件入口:菜单、同步运行时、想法弹窗点按拦截
└── pickthought/
    ├── api.lua / http.lua / auth.lua / cookies.lua   # 微信读书 web 接口与登录(自动续期)
    ├── web_fetch.lua         # 数据源:热门划线 + 章节公开想法
    ├── sync.lua              # 同步编排:拉取→缓存→映射→注入→替换(依赖注入可测)
    ├── sync_task.lua         # 后台子进程任务:进度/取消/断点/看门狗/保持唤醒
    ├── sync_progress.lua     # 进度对话框(取消 / 后台)
    ├── chapter_map.lua       # 章节映射:引文投票、拆分章、章名兜底、结果缓存
    ├── annotations.lua       # 注入引擎:分词、引文定位、锚点注入
    ├── annotation_style.lua  # 划线虚线样式
    ├── epub_reader.lua       # ffi/archiver 之上的 EPUB 元数据解析
    ├── epub_inject.lua       # 注入编排:流式锚点写入 + 重打包
    ├── binding.lua           # 本地书 ↔ 微信书目绑定
    ├── thoughts.lua          # 想法数据层(SQLite 后端 + 弹窗文本格式化)
    ├── thought_db.lua        # per-book SQLite 想法存储(移植自 weread.koplugin)
    ├── store.lua / config.lua                         # 本地存储与配置
    ├── updater.lua           # 插件在线更新
    └── async.lua / digests.lua / json.lua / protocol.lua / text.lua / util.lua
```

桌面测试(无需 KOReader 环境,使用 KOReader stub 与内存 Archiver/SQLite mock):

```bash
luajit tests/run.lua
```
