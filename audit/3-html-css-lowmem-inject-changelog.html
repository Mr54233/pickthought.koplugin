低内存 HTML/CSS 注入优化 — 更新日志

插件 pickthought.koplugin (KOReader, AGPL-3.0) · PR #1 · 分支 pr/html-css-inject · 修改日期 2026-08-13

动机

  • CRE 渲染引擎按「带样式元素单价 × 数量」计费;基线 cre_storage_size_factor=40 仅约 10MB 预算。
  • 大量「每标注唯一 class + 虚线 border-bottom 盒子」会撑爆样式数据缓存,导致 KPW3 开书段错误崩溃(见此前崩溃日志;《神秘复苏》7015 个虚线边框 span 即崩)。
  • 目标:把所有注入元素压到最便宜的样式(文本级),在预算内承载更大注入量。

具体改动点

文件改动
annotations.lua 去掉每标注唯一 class pickthought-mark-<hex>(含其 Thoughts.mark_class 调用);碰撞锚点改用 <a class="pickthought-link pickthought-mark" data-pickthought-range href>;折叠 2 个样式元素为 1。
annotation_style.lua border-bottom 虚线 → text-decoration(文本级样式,单价≈0)。
tests/test_epub_inject.lua 断言跟进:折叠后类落到 <a> 上(原断言 class="pickthought-mark 改为锚点 <a>)。

影响范围

  • 仅注入期 HTML 生成与 CSS;锚点弹出 / 跳转功能不变。
  • 唯一标识由 data-pickthought-range 与 href 承载,去掉唯一 class 后样式零变化、功能不受影响。
  • 未引入多书(D)逻辑。

校验结果

  • LuaJIT 语法校验:通过。
  • 单元测试: 123 passed / 0 failed(基线 120 + 本 PR 3 项 EPUB 注入断言更新)。
  • 多书(D)残留扫描: 0(annotations.lua / annotation_style.lua 均无 book_ids / multi_book / ch.book_id / merge.book_id)。
